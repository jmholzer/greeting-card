# Instructions for coding agents

## PR descriptions, PR comments and review replies

A human must be able to read the text in 15 seconds. Optimise for brevity.

- Use exactly two sections: `## Description` and `## Testing`.
- Description: one short sentence describing the change, then at most three short bullet points describing the technical approach.
- Testing: as few short bullet points as possible describing how the change was tested.
- Put essential merge notes (such as a dependency on another PR or a required migration) in a short bullet inside these sections.
- Do not use emojis, em dashes or other exotic punctuation.
- Apply the same brevity and punctuation rules to PR comments and review replies.
